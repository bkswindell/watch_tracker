# Phase 1 builder status

**Checkpoint:** `789f4b061908fb0b3987b61110d812e6be47941e` — `fix(auth): preserve credential-locked login session`

- **Delivered recovery gate:** a repository-conventional host-admin CLI now creates a 256-bit random, 15-minute, fragment-only reset link and writes it exactly once to stdout. PostgreSQL stores only SHA-256 digests bound to the singleton Tracker instance; issuing a link atomically invalidates prior outstanding links. Completion atomically claims a valid unexpired token, applies the existing Argon2id/password policy, updates the credential, and deletes all sessions. Invalid, expired, superseded, reused, cross-owner, malformed, and policy-invalid submissions use the same generic API failure.
- **UI/security behavior:** `/reset-password` is a production-served SPA entry with `Cache-Control: no-store` and `Referrer-Policy: no-referrer`. The React UI reads the URL fragment once, immediately replaces the URL, keeps the token only in memory, sends it only in the same-origin POST body, clears reset/password state after an attempt, uses new-password autocomplete, and does not use browser storage, logs, analytics, or query strings. Login authentication/session creation is serialized against recovery so an in-flight old-password login cannot survive reset revocation.
- **Schema/API/CLI/UI tests:** migration `0.09` and schema integrity checks cover digest format, owner FK, expiry, and one-use state. Portable tests cover token entropy, 15-minute expiry, supersession, concurrent single use, session revocation, old/new password behavior, generic failures, exact Origin, no-store/no-referrer, fragment-only CLI URLs, once-only stdout, no browser storage/logging, and the production reset-page fallback. PostgreSQL integration covers digest-only persistence, supersession, concurrent atomic use, owner isolation, expiry, credential replacement, and session deletion.
- **Login/reset race correction:** login now returns the session created while the credential row is locked, instead of silently creating a second session after the lock is released. This closes the interval in which a completed password reset could revoke the authenticated session and a second old-password session could subsequently be created. A regression test counts session creation and requires exactly one session for a successful login.
